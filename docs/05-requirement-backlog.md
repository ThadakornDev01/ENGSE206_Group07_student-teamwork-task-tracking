# 05 — Requirement Backlog and Prioritization

> **Week 5 deliverable**
> Requirement ต้องระบุได้ ตรวจสอบได้ และเชื่อมโยงกับ stakeholder/value ที่ชัดเจน

## 1. Prioritization Method

เลือกใช้วิธีหนึ่ง เช่น MoSCoW, Value vs Effort, Kano หรือวิธีที่อาจารย์กำหนด

- **วิธีที่ใช้:** MoSCoW (Must / Should / Could / Won't)
- **หลักเกณฑ์:**
  - **Must** — requirement ที่ตอบ Pain Point ระดับสูง (PP-02, PP-03) หรือเป็นเงื่อนไขที่ระบบใช้งานไม่ได้เลยถ้าขาดไป (เช่น การมอบหมายงาน การแนบหลักฐาน การจำกัดสิทธิ์ตามบทบาท)
  - **Should** — requirement ที่เพิ่มคุณค่าให้กับความเป็นธรรมและความน่าเชื่อถือของข้อมูล (เช่น ประวัติการเปลี่ยนเจ้าของงาน) แต่ระบบยังใช้งานหลักได้แม้ยังไม่มีในรอบแรก
  - **Could** — requirement ที่ช่วยให้ทีมทำงานสะดวกขึ้นแต่ไม่กระทบ Pain Point หลัก
  - **Won't (รอบนี้)** — requirement ที่อยู่นอกขอบเขตตาม `docs/01-problem-brief-v0.1.md` (เช่น Chat, Video call, เชื่อมระบบคะแนนมหาวิทยาลัย)
