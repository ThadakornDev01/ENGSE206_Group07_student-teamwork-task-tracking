## 2. Acceptance Criteria

### AC-01: การแสดงรายการงานและกำหนดส่ง (Linked: US-01 / FR-01)[cite: 2]
* **AC-01-01 (Happy Path):**
  * **Given** สมาชิกกลุ่มเข้าสู่ระบบสำเร็จ[cite: 2]
  * **When** เปิดเข้ามายังหน้าหลัก (Task Board / My Tasks)[cite: 2, 3]
  * **Then** ระบบต้องแสดงรายการงานทั้งหมดที่ตนเองรับผิดชอบ พร้อมชื่อหัวข้องาน สถานะปัจจุบัน และวันกำหนดส่งอย่างชัดเจน โดยไม่ต้องตั้งตัวกรองค้นหาเอง[cite: 2]
* **AC-01-02 (Empty State):**
  * **Given** สมาชิกยังไม่ได้รับมอบหมายงานใดๆ
  * **When** เปิดดูหน้ารายการงานของตนเอง
  * **Then** ระบบต้องแสดงข้อความว่า "ยังไม่มีงานที่ได้รับมอบหมายในขณะนี้"

### AC-02: การสร้างและมอบหมายงาน (Linked: US-02 / FR-02)[cite: 2]
* **AC-02-01 (Success):**
  * **Given** ผู้ใช้เข้าสู่ระบบด้วยสิทธิ์ "หัวหน้ากลุ่ม"[cite: 2]
  * **When** กรอกชื่องาน, เลือกผู้รับผิดชอบจากรายชื่อสมาชิกในกลุ่ม, ระบุวันกำหนดส่ง แล้วกดปุ่ม "สร้างงาน"[cite: 2]
  * **Then** งานชิ้นใหม่ต้องบันทึกลงระบบ และไปปรากฏในรายการงานของผู้รับผิดชอบทันที[cite: 2]
* **AC-02-02 (Validation Check):**
  * **Given** หัวหน้ากลุ่มกำลังสร้างงานใหม่
  * **When** ไม่ระบุชื่อผู้รับผิดชอบ หรือเว้นว่างวันกำหนดส่ง แล้วกดบันทึก
  * **Then** ระบบต้องปฏิเสธการบันทึก และแจ้งเตือนให้กรอกข้อมูลจำเป็นให้ครบถ้วน

### AC-03: การอัปเดตสถานะงานเรียลไทม์ (Linked: US-03 / FR-03, BR-02)[cite: 2]
* **AC-03-01 (State Transition & Real-time):**
  * **Given** สมาชิกเปิดการ์ดงานที่ตนเองเป็นเจ้าของ[cite: 2]
  * **When** ทำการเปลี่ยนสถานะงานจาก "To-do" เป็น "Doing"
  * **Then** สถานะงานเปลี่ยนเป็น Doing ทันที และหน้าจอของสมาชิกคนอื่นในกลุ่มเห็นการเปลี่ยนแปลงโดยไม่ต้องรีเฟรชหน้าจอเกิน 1 ครั้ง[cite: 2]

### AC-04: การบังคับแนบหลักฐานก่อนปิดงาน (Linked: US-04 / FR-04, BR-01)[cite: 2]
* **AC-04-01 (Validation Enforcement - Rule BR-01):**
  * **Given** สมาชิกกำลังเปิดการ์ดงานสถานะ "Doing"
  * **When** พยายามเลือกสถานะเป็น "Done" โดยยังไม่ได้อัปโหลดไฟล์ แนบ URL ลิงก์ หรือพิมพ์ข้อความหลักฐาน[cite: 2]
  * **Then** ระบบต้องปฏิเสธการเปลี่ยนสถานะ และแสดงข้อความเตือนให้แนบหลักฐานการทำงานก่อนเสมอ[cite: 2]
* **AC-04-02 (Success Submission):**
  * **Given** สมาชิกแนบไฟล์หรือวางลิงก์หลักฐานภายนอก (เช่น Google Drive, GitHub) ลงในช่องหลักฐานเรียบร้อยแล้ว[cite: 2, 3]
  * **When** กดยืนยันเปลี่ยนสถานะเป็น "Done"
  * **Then** สถานะงานเปลี่ยนเป็น Done สำเร็จ และบันทึกหลักฐานนั้นผูกติดไว้กับการ์ดงาน[cite: 2]

### AC-05: ประวัติการเปลี่ยนผู้รับผิดชอบงาน (Linked: US-05 / FR-05, BR-04, NFR-04)[cite: 2, 13]
* **AC-05-01 (Audit Trail):**
  * **Given** หัวหน้ากลุ่มทำการเปลี่ยนผู้รับผิดชอบงานจากสมาชิก A เป็นสมาชิก B[cite: 2]
  * **When** กดยืนยันการมอบหมายใหม่
  * **Then** ระบบต้องบันทึกประวัติ (History Log) ระบุชื่อคนเดิม, ชื่อคนใหม่, วันเวลา (Timestamp) และคงไฟล์งานเดิมไว้ครบถ้วน[cite: 2]
* **AC-05-02 (Psychological Usability - NFR-04):**
  * **Given** สมาชิกเปิดดูแถบ Task History Log[cite: 3]
  * **When** มีรายการเปลี่ยนตัวผู้รับผิดชอบงาน
  * **Then** ข้อความที่แสดงต้องใช้ภาษาที่เป็นกลาง (Neutral wording) เช่น "ส่งมอบงานต่อให้ [ชื่อสมาชิก]" โดยไม่มีข้อความเชิงลบหรือตำหนิบน UI[cite: 2, 7]

### AC-06: สิทธิ์และการแสดงผล Dashboard ของอาจารย์ (Linked: US-06 / FR-06, FR-07, BR-03, NFR-01)[cite: 2]
* **AC-06-01 (Read-only Restriction - BR-03):**
  * **Given** อาจารย์ผู้สอนเข้าสู่ระบบและเปิดดูหน้ารายละเอียดกลุ่ม 07[cite: 2]
  * **When** เปิดหน้า Dashboard สรุปความคืบหน้า[cite: 2]
  * **Then** ระบบต้องแสดงสัดส่วนงานที่เสร็จ (Done) และงานคงค้างของสมาชิกแต่ละคนในรูปแบบอ่านอย่างเดียว (Read-only) โดยไม่มีปุ่มแก้ไข/ลบงาน[cite: 2]
* **AC-06-02 (Privacy & Evidence Access - NFR-02, IS-02):**
  * **Given** อาจารย์เปิดดูรายการงานของกลุ่ม[cite: 2]
  * **When** คลิกดูรายละเอียดงาน[cite: 2]
  * **Then** อาจารย์สามารถคลิกเปิดดูไฟล์หลักฐานของงานสถานะ "Done" ได้ แต่ระบบต้องไม่แสดงรายละเอียดการสื่อสารภายในหรืองานระหว่างทำ (Work-in-progress)[cite: 2, 7]

### AC-07: การทำแบบประเมินอิงหลักฐาน (Linked: US-07 / FR-08, BR-04)[cite: 2]
* **AC-07-01 (Evidence-backed Evaluation):**
  * **Given** สมาชิกเข้าสู่ระบบในช่วงเปิดรอบทำ Peer Evaluation เมื่อสิ้นสุดโปรเจกต์[cite: 2]
  * **When** เปิดแบบฟอร์มประเมินเพื่อนร่วมทีม[cite: 2]
  * **Then** ระบบต้องดึงรายการงานและลิงก์หลักฐานที่เพื่อนคนนั้นทำเสร็จ (Done) มาแสดงบนหน้าจอควบคู่กับเกณฑ์การให้คะแนน[cite: 2, 3]

### AC-08: การสรุปคะแนน Peer Evaluation (Linked: US-08 / FR-09)[cite: 2]
* **AC-08-01 (Automated Calculation):**
  * **Given** สมาชิกทุกคนในกลุ่มส่งแบบประเมินครบถ้วน[cite: 2]
  * **When** อาจารย์ผู้สอนหรือหัวหน้ากลุ่มเปิดดูรายงานผลสรุป[cite: 2]
  * **Then** ระบบต้องคำนวณคะแนนเฉลี่ยและสรุป Feedback ข้อคิดเห็นของสมาชิกแต่ละคนออกมาให้อัตโนมัติโดยไม่ต้องรวบรวมเอง[cite: 2]

### AC-09: การเข้าถึงสำหรับผู้บกพร่องทางการมองเห็น (Linked: US-09 / R-1, R-2)[cite: 11]
* **AC-09-01 (Keyboard Trapping & Navigation):**
  * **Given** สมาชิกใช้งานผ่านคีย์บอร์ดโดยไม่ใช้เมาส์[cite: 11]
  * **When** กดปุ่ม Tab, Shift+Tab, Enter และ Space[cite: 14]
  * **Then** ผู้ใช้ต้องสามารถเลื่อน Focus ไปยังปุ่ม ฟอร์ม และสั่งเปลี่ยนสถานะงานได้ครบถ้วน โดยไม่ติดกับดักคีย์บอร์ด (No mouse trap)[cite: 11, 14]
* **AC-09-02 (Screen Reader Compatibility):**
  * **Given** สมาชิกเปิดโปรแกรม Screen Reader (เช่น NVDA / VoiceOver)[cite: 14]
  * **When** Focus เลื่อนไปยังการ์ดงานและปุ่มคำสั่ง[cite: 14]
  * **Then** โปรแกรมอ่านหน้าจอต้องอ่านชื่อป้ายกำกับ (ARIA Label) สถานะงาน และข้อความแจ้งเตือนออกมาเป็นเสียงสังเคราะห์ได้อย่างถูกต้อง[cite: 11, 14]

### AC-10: การทำงานออฟไลน์และซิงก์ข้อมูล (Linked: US-10 / R-3, R-4)[cite: 14]
* **AC-10-01 (Local Cache Reading):**
  * **Given** อุปกรณ์ของสมาชิกขาดการเชื่อมต่ออินเทอร์เน็ตระหว่างใช้งาน[cite: 14]
  * **When** เปิดดูรายการงานและกำหนดส่ง[cite: 14]
  * **Then** ระบบต้องดึงข้อมูลล่าสุดจากแคชภายในเครื่องมาแสดงผลได้ต่อเนื่อง พร้อมแสดงแถบเตือนสถานะ Offline[cite: 14]
* **AC-10-02 (Action Queue & Auto-sync):**
  * **Given** ผู้ใช้กดเปลี่ยนสถานะงานในขณะที่ระบบอยู่ในสถานะ Offline[cite: 14]
  * **When** สัญญาณอินเทอร์เน็ตกลับมาเชื่อมต่อสำเร็จ[cite: 14]
  * **Then** คำสั่งที่ค้างอยู่ในคิวภายในเครื่องต้องถูกส่งขึ้นเซิร์ฟเวอร์ และอัปเดตสถานะงานให้อัตโนมัติโดยข้อมูลไม่สูญหาย[cite: 14]
