## 1. Introduction

### 1.1 Purpose
เอกสาร Software Requirements Specification (SRS) ฉบับนี้ จัดทำขึ้นเพื่อรวบรวมข้อกำหนดความต้องการของ "ระบบติดตามงานกลุ่มและการแบ่งบทบาทสมาชิก"

โดยเอกสารนี้รวบรวมข้อกำหนดจาก Week 05 (Requirement Backlog) และแบบจำลองจาก Week 06 (Requirement Models) เพื่อจัดทำเป็น specification ที่สามารถตรวจสอบย้อนกลับ (Traceable) ได้ โดยไม่เพิ่ม requirement จากเอกสารตัวอย่างที่อยู่นอก source ของ STTT

### 1.2 Scope

### In Scope
1. การจัดการภาระงาน (การแสดงบทบาท ความคืบหน้า วันกำหนดส่ง)
2. การแนบหลักฐานการทำงาน (รองรับไฟล์, ลิงก์, หรือข้อความ)
3. ระบบรองรับกระบวนการและข้อตกลง Peer Evaluation ภายในกลุ่ม
4. รองรับการทำงานในระดับ 1 รายวิชา / 1 โครงการ

### Out of Scope
1. ไม่รวมระบบ Chat หรือ Video call ภายในตัว
2. ไม่เชื่อมต่อกับระบบให้คะแนนหรือระบบบริหารการศึกษาของมหาวิทยาลัย
3. ไม่ทำระบบ Timesheet หรือระบบบริหารโครงการระดับองค์กร

## 2. Overall Description

### 2.1 Product Perspective
ระบบติดตามงานกลุ่มและการแบ่งบทบาทสมาชิก (Student-teamwork-task-tracking) เป็นระบบซอฟต์แวร์แบบ Stand-alone ที่ออกแบบมาเพื่อการใช้งานในระดับรายวิชาหรือโครงการเดียว ระบบนี้ไม่ได้ถูกออกแบบมาเพื่อทดแทนแอปพลิเคชันแชตที่นักศึกษาใช้อยู่เดิม (เช่น LINE, Facebook Messenger) และไม่ได้มีการเชื่อมต่อ (Integration) เข้ากับระบบบริหารการศึกษาหรือระบบฐานข้อมูลคะแนน (Grading System) ของมหาวิทยาลัยโดยตรง

ระบบจะทำหน้าที่เป็นศูนย์กลาง (Centralized Tracker) ในการมอบหมายงาน อัปเดตความคืบหน้า และที่สำคัญที่สุดคือเป็นพื้นที่สำหรับจัดเก็บ "หลักฐานการทำงาน (Evidence)" ของสมาชิกแต่ละคนอย่างเป็นระบบ เพื่อนำข้อมูลเชิงประจักษ์เหล่านี้ไปใช้ลดความขัดแย้งในการทำแบบประเมินเพื่อนร่วมทีม (Peer Evaluation) และช่วยให้อาจารย์ผู้สอนมีข้อมูลที่น่าเชื่อถือในการประเมินผลการเรียน

## 3. Functional Requirements

| FR-01 | ระบบต้องแสดงรายการงานพร้อมกำหนดส่งของสมาชิกแต่ละคนให้เจ้าของงานเห็นได้ทันทีที่ล็อกอิน | Must | สมาชิกเห็นงานของตนเองครบทุกชิ้นพร้อมวันกำหนดส่ง โดยไม่ต้องกรองข้อมูลเอง | Ready |
| FR-02 | ระบบต้องให้หัวหน้ากลุ่มสร้างงานใหม่และมอบหมายผู้รับผิดชอบพร้อมกำหนดส่งได้ | Must | สร้างและมอบหมายงาน 1 ชิ้นสำเร็จภายใน 3 ขั้นตอน และงานปรากฏในรายการของผู้รับผิดชอบ | Ready |
| FR-03 | ระบบต้องแสดงสถานะความคืบหน้าของงานแต่ละชิ้น (เช่น To do / Doing / Done) และอัปเดตแบบเรียลไทม์เมื่อสมาชิกเปลี่ยนสถานะ | Must | เมื่อสมาชิกเปลี่ยนสถานะ หัวหน้ากลุ่มเห็นการเปลี่ยนแปลงโดยไม่ต้องรีเฟรชเกิน 1 ครั้ง | Ready |
| FR-04 | ระบบต้องอนุญาตให้สมาชิกแนบหลักฐานการทำงาน (ไฟล์ ลิงก์ หรือข้อความ) เข้ากับงานที่ตนรับผิดชอบได้ | Must | แนบหลักฐานได้อย่างน้อย 3 รูปแบบ (ไฟล์/ลิงก์/ข้อความ) และหลักฐานผูกกับงานที่ถูกต้อง | Ready |

| FR-09 | ระบบต้องรวบรวมผล Peer Evaluation เป็นสรุปคะแนน/feedback ให้หัวหน้ากลุ่มและอาจารย์เห็น | Should | สรุปผลประเมินแสดงคะแนนเฉลี่ยและความเห็นของแต่ละคนโดยไม่ต้องรวมข้อมูลเอง | Ready |

| FR-11 | ระบบต้องแยกสิทธิ์การเข้าถึงตามบทบาท (สมาชิก / หัวหน้ากลุ่ม / อาจารย์) เพื่อจำกัดว่าใครเห็น/แก้ไขข้อมูลใดได้ | Must | ผู้ใช้แต่ละบทบาททำได้เฉพาะสิทธิ์ที่กำหนดเมื่อทดสอบด้วยบัญชี 3 บทบาท | Ready |
| FR-12 | ระบบต้องให้ทีมบันทึกข้อตกลงการทำงานร่วมกัน (team agreement / เกณฑ์ peer evaluation) ไว้ตั้งแต่ต้นโครงการ | Could | ทีมบันทึกข้อตกลงได้ 1 ฉบับ และสมาชิกทุกคนเปิดดูได้ตลอดโครงการ | Needs Follow-up |

## 8. External Interface Requirements

### 8.1 User Interfaces
- Mobile Responsive: ระบบต้องรองรับการแสดงผลและใช้งานได้อย่างสมบูรณ์ทั้งบนคอมพิวเตอร์และสมาร์ตโฟน (Web-based/Mobile Responsive) โดยไม่ต้องซูมหน้าจอ เนื่องจากกลุ่มผู้ใช้งานหลักคือนักศึกษาที่มักอัปเดตงานผ่านโทรศัพท์มือถือ.   
- Task Board (Student View): หน้าจอของนักศึกษาต้องแสดงรายการงาน ผู้รับผิดชอบ และกำหนดส่งแยกออกมาจากช่องแชตอย่างชัดเจน เพื่อป้องกันปัญหาข้อมูลกระจัดกระจาย.   
- Instructor Dashboard (Read-only): หน้าจอสำหรับอาจารย์ต้องถูกออกแบบให้เป็นมุมมองภาพรวม (Dashboard) ที่แสดงกราฟสัดส่วนงานที่เสร็จและงานค้างของแต่ละกลุ่ม โดยอาจารย์จะมีสิทธิ์เพียงคลิกดูหลักฐาน (Read-only) และระบบจะไม่แสดงรายละเอียดการคุยงานหรือความผิดพลาดระหว่างการทำงาน (Work in progress) เพื่อรักษาสภาพจิตใจและพื้นที่ปลอดภัยของนักศึกษา.   
- Psychological Usability (Neutral Wording): หน้าจอแสดงประวัติการเปลี่ยนเจ้าของงาน (History Log) ต้องใช้คำที่เป็นกลาง ไม่มีข้อความในเชิงตำหนิหรือแสดงข้อผิดพลาดของบุคคลอย่างโจ่งแจ้ง เพื่อลดความขัดแย้งภายในทีม.

### 8.2 Software / External System Interfaces
 - Stand-alone System: ระบบนี้ทำงานเป็นเอกเทศ โดยจะ ไม่เชื่อมต่อ (Integration) กับระบบประเมินเกรด หรือระบบบริหารการศึกษาของมหาวิทยาลัยโดยตรง.   
 - No Internal Chat/Video: ระบบไม่มีการเชื่อมต่อหรือฝังฟีเจอร์แชตและวิดีโอคอลไว้ภายในตัว โดยสันนิษฐานว่านักศึกษาจะใช้แอปพลิเคชันภายนอก (เช่น LINE, Facebook Messenger) ในการสื่อสารตามปกติ และใช้ระบบนี้เพื่อการจัดเก็บหลักฐานและอัปเดตสถานะเท่านั้น.   
 - External Cloud Support: ระบบอนุญาตให้ผู้ใช้ส่งหลักฐานเป็นลิงก์ (URL) ที่เชื่อมโยงไปยังระบบฝากไฟล์ภายนอก (เช่น Google Drive, GitHub) ได้ เพื่อลดภาระการจัดเก็บข้อมูลของเซิร์ฟเวอร์.   

### 8.3 Data Interfaces
- Evidence Upload & Validation: การเปลี่ยนสถานะงานเป็น "เสร็จสิ้น (Done)" ระบบจะรับส่งข้อมูลหลักฐานผ่าน 3 รูปแบบหลัก ได้แก่ การอัปโหลดไฟล์ตรงเข้าสู่ระบบ, การป้อน URL ภายนอก, หรือการพิมพ์ข้อความอธิบาย.   
- Data Isolation (Privacy): ระบบมีการแยกฐานข้อมูลตามรายวิชาและตามกลุ่มอย่างเด็ดขาด (Role-based access) โดยข้อมูลและหลักฐานของแต่ละกลุ่มจะถูกมองเห็นได้เฉพาะสมาชิกภายในกลุ่มนั้นและอาจารย์ผู้สอนประจำวิชาเท่านั้น.   
- Immutable Audit Log: ข้อมูลประวัติการโอนย้ายงาน (History Log) จะถูกบันทึกพร้อม Time-stamp ทันทีที่มีการสับเปลี่ยน โดยระบบจะบล็อกไม่ให้มีการส่งคำสั่งลบหรือแก้ไขข้อมูลส่วนนี้ย้อนหลังโดยเด็ดขาด.

## Appendix B — AI Use Disclosure
**วัตถุประสงค์และขอบเขตการใช้งาน (Use Cases):**
   * ใช้ AI ช่วยตรวจสอบและปรับปรุงคำถามสัมภาษณ์ เพื่อป้องกันการใช้คำถามชี้นำ (Leading Questions) ใน Week 03
   * ใช้ AI จำลองสถานการณ์สัมภาษณ์ (Role-play Rehearsal) สวมบทบาทเป็น "หัวหน้ากลุ่ม" และ "อาจารย์ผู้สอน" เพื่อทดสอบความชัดเจนของคำถามก่อนสัมภาษณ์จริง
   * ใช้ AI ช่วยจัดโครงสร้างตาราง Markdown, จัดกลุ่ม Requirement, และตรวจสอบความเชื่อมโยงย้อนกลับ (Traceability) จาก Week 05 และ Week 06 มายังเอกสาร SRS

**การคุ้มครองข้อมูลและความเป็นส่วนตัว (Privacy & Ethics):**
   * ไม่มีการป้อนข้อมูลส่วนบุคคลที่สามารถระบุตัวตนได้ (PII) เช่น ชื่อจริง-นามสกุล, รหัสนักศึกษา, ผลการเรียนจริง, หรือข้อความสนทนาส่วนตัวลงใน Prompt ของ AI โดยเด็ดขาด
   * ข้อมูลและสถานการณ์จำลองทั้งหมดใช้บทบาทสมมติ (Role-based) ในการอ้างอิงเท่านั้น
